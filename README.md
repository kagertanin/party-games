# Party Games

Браузерные игры для компании. Первый режим — «Шляпа».

## Сто к одному

Откройте `?game=survey` и нажмите «Играть», чтобы настроить партию на одном экране. Игра поддерживает 4–15 участников и 2–3 команды по 2–5 человек. «Демо» сразу запускает партию на 12 участников с подсказками. Перед каждым из трёх вопросов все участники голосуют за одну из трёх тем. Голосование длится до 20 секунд, отсчёт виден в последние 10. Участников можно переключать списком под темами.

На каждый вопрос есть два круга по одному ходу команды. Перед ходом есть до 20 секунд на готовность. Если подтвердили все, ход начинается сразу. В первом круге партии отсчёт готовности виден в последние 10 секунд. В этом же круге у каждой команды три минуты на ход, а отсчёт хода виден только в последние 30 секунд. Дальше на ход одна минута с видимым отсчётом. Последние 10 секунд каждого хода отведены голосованию. Отправьте решение команды, удерживая «Подтвердить выбор» две секунды.

Переключатель «Команда в демо» показывает игру глазами выбранной команды или по очереди от лица всех команд. Нажатие на команду в списке показывает только её состав. Зрители видят предложенные ответы и кто за них голосовал. Спираль показывает очерёдность и результаты ходов.

В комнате ожидания ведущий может выбрать набор «Классика» или «18+» и пролистать формулировки. Перед каждым раундом сервер предлагает три вопроса из перемешанной колоды. Уже показанные вопросы возвращаются в колоду после того, как использован весь набор.

«Классика» переведена из [раздела ProtoQA с опросами](https://github.com/iesl/protoqa-data/blob/master/data/dev/dev.crowdsourced.jsonl) (Boratko и др., 2020, [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)). Для каждого вопроса сохранены частоты шести групп ответов и добавлены русские варианты написания. «18+» адаптирован по темам [открытых подборок Familio Games](https://www.familiogames.com/family-feud-questions-for-adults). В этом наборе используются игровые очки.

### Журнал действий

Сервер «Сто к одному» записывает сетевые события в JSONL, по одному событию на строку. В журнале есть время в UTC, действие, результат обработки, этап партии и игровой контекст. Для комнат используются случайные идентификаторы. Псевдоним игрока действует в пределах одной комнаты. Журнал хранится без имён, кодов комнат и текстов ответов.

На Amvera журнал по умолчанию лежит в `/data/survey-metrics/survey-ГГГГ-ММ-ДД.jsonl`. Файлы доступны администратору через «Репозиторий» → «Data». Свежие события видны в журнале приложения с префиксом `survey-metrics `. При записи в новый день удаляются файлы старше 30 дней. Объём записи ограничен 8 МиБ в сутки. Для локального запуска укажите каталог в `SURVEY_METRICS_DIR`, например `SURVEY_METRICS_DIR=/tmp/party-survey-metrics npm run server`. [Постоянное хранилище Amvera](https://docs.amvera.ru/common_questions/data.html)

## Что работает

- Полная демонстрационная партия на одном устройстве: 4–15 участников, команды до четырёх человек, пять слов от игрока, два круга, очки и повторная партия.
- В демо участники уже добавлены. Пользователь управляет всеми командами, вводит свои пять слов и сам отмечает ответы. Остальные слова подготовлены заранее. Демо не имитирует подключение реальных друзей.
- Сохранение демопартии в браузере, пауза и ручное завершение таймера для проверки переходов. При возврате в закрытую демопартию время текущего хода начинается заново.
- Сервер Colyseus и браузерное подключение, готовые для отдельного Node.js-хостинга. Rooms живут в памяти. Секретное слово отправляется только объясняющему.

Sites публикует статическую демонстрацию. Сетевые комнаты станут доступны после размещения сервера и указания `VITE_SERVER_URL` при сборке клиента. Голосовой разговор проходит в отдельном созвоне.

## Разработка

Нужен Node.js 22 или 24.

```sh
npm ci
npm run dev
npm test
npm run build
```

Сервер и клиент в локальной сетевой проверке:

```sh
VITE_SERVER_URL=http://localhost:2567 npm run build
npm run server
```

Затем открыть `http://localhost:2567`. Для подключения с другого устройства задайте доступный ему адрес вместо localhost. Сервер отдаёт и собранный сайт, и игровые соединения с одного порта.

`npm run check:network` проверяет работающий сервер (по умолчанию localhost:2567). Переопределение — `TEST_SERVER_URL`. Сценарий создаёт свою комнату и отключает тестовых участников после завершения. Пустая комната удаляется через пять минут.

## Правила

1. Команды распределяются максимально равномерно, до четырёх человек. Для первой версии нужно минимум четыре игрока.
2. Каждый добавляет пять уникальных слов или коротких выражений. Нормализация повторов игнорирует регистр, лишние пробелы и различие е/ё.
3. Круг 1: один ход по 60 секунд на команду, объяснения без самого слова и однокоренных. Пропущенная карточка возвращается в конец колоды.
4. Круг 2: только угаданные в первом круге карточки. Начинают лидеры круга 1, равенство сохраняет исходный порядок. Одна новая подсказка из одного слова на попытку. Подсказка вводится текстом, чтобы запретить её повторение.
5. На попытку 20 секунд. При успехе команда получает новую карточку и продолжает до трёх угаданных подряд. После трёх ход передаётся со следующей карточкой. После тайм-аута передаётся та же карточка вместе с историей подсказок.
6. Объясняющий меняется при передаче хода. Если та же карточка вернулась, её объясняет тот же человек, чтобы знающий ответ не стал угадывающим.
7. За карточку одно очко в каждом круге. Победитель по сумме, возможна ничья.
8. Чтобы партия не зависала, после двух полных обходов команд без ответа карточка исключается без очков. Это начальное допущение для проверки с игроками.

## Архитектура

- `shared/game.ts` — общий автомат правил. Клиентская демонстрация и авторитетный сервер используют одну реализацию.
- `src/` — интерфейс на TypeScript, HTML и CSS. Шрифт Rubik включён в сборку, внешних запросов к шрифтовым сервисам нет.
- `server/index.ts` — комнаты Colyseus, индивидуальные снимки состояния, переподключение и раздача сайта.
- `tests/` — проверки правил, секретности и сетевого сценария.

В демо все данные доступны локально для управления командами. В сетевом режиме `view()` исключает колоду, чужие слова и ответ из сообщений угадывающим. Сервер проверяет автора действия, фазу и дедлайн. Состояние комнат и ключи возврата теряются при перезапуске процесса.

Отключённый игрок может вернуться по токену в течение пяти минут. Пустая комната удаляется через пять минут. Для долгого отключения объясняющего первую версию можно продолжить после окончания таймера, его ход перейдёт дальше. Повторная партия сохраняет подключённых игроков и тот же адрес комнаты.

## Публикация

Исходники хранятся в `kagertanin/party-games`. Репозиторий был создан владельцем публичным, этот статус сохранён. Открытая лицензия на собственный код проекта пока не назначена.

CI проверяет правила и сборку. Обновление Sites выполняется средствами Sites, конфигурация находится в `.openai/hosting.json`. Автоматическое размещение на VPS добавляется после выбора хостинга. Dockerfile подготовлен для запуска сервера с сайтом. В `VITE_SERVER_URL` указывается HTTPS-адрес внешнего сервера.

```sh
docker build --build-arg VITE_SERVER_URL=https://games.example.com -t party-games .
docker run --rm -p 2567:2567 party-games
```

HTTPS должен завершаться на прокси хостинга. Игровые комнаты не сохраняются между обновлениями контейнера.
